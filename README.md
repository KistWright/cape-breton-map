# Cainnt is Ceathramhan

This repository generates a standalone bilingual map application showing:

- Cape Breton communities
- people linked to those communities
- Scottish traditions linked back to Cape Breton

The current build is generated by one Python script. The browser-side app is not
hand-coded separately.

## Start here

The key file is `generate_map.py`.

A new developer should read these parts in this order:

1. the developer notes at the top of `generate_map.py`
2. `main()`
3. the `clean_*` functions
4. the figure builders
5. `render_html()`

That gives the quickest route to understanding how the build works end to end.

## What the script expects

Working inputs currently used by the build:

```text
generate_map.py
places.csv
people.csv
communities.csv
traditions.csv
CBscot.svg
SCOTcb.svg
map_controls.svg
```

Generated output:

```text
cape_breton_people_map.html
```

For GitHub Pages or similar static hosting, this file is often renamed to
`index.html` after build.

## Current app behaviour

The current generated HTML supports:

- a Cape Breton main map
- a Scotland map
- a dedicated Cape Breton inset figure
- map-view swapping between Cape Breton and Scotland
- three panel modes: Places, People, Traditions
- Gaelic / English UI labels
- sort controls for lists
- expandable person cards
- person detail-level controls in the People tab
- a floating inset / traditions panel
- per-tradition overlay toggling
- reset and list-management controls
- a map-controls popup loaded from `map_controls.svg`
- outbound links to person pages and recordings

## Build command

Run from the project directory:

```bash
python generate_map.py
```

## Known current assumptions

- `places.csv` holds both Cape Breton communities and Scottish origin places.
- `people.csv` links people to Cape Breton place keys via `Place number`.
- `communities.csv` maps Cape Breton communities to tradition place keys.
- `traditions.csv` maps tradition place keys back to Cape Breton communities.
- the browser relies on Python-exported JSON data and prebuilt Plotly traces
  rather than building map layers from scratch in JavaScript
- the Cape Breton inset is a separate figure, not just a resized version of the
  main Cape Breton map

## Files worth protecting from casual edits

The easiest places to break the build are:

- CSV headers
- shared key names passed from Python into JavaScript
- Plotly trace ordering
- HTML element ids used by JavaScript
- inline CSS/JS inside `render_html()`

## Minimum smoke test after any change

Open the rebuilt HTML and test:

1. the map swap buttons
2. all three side tabs
3. a place click
4. a person selection
5. a tradition overlay toggle
6. Clear List / Restore List / Show All Traditions
7. Reset Map
8. the map-controls popup
9. person and recordings links
